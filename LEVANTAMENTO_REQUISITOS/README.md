# 📚 Plano de Aula: Engenharia de Requisitos

## 1. Introdução aos Requisitos de Software
### Requisitos Funcionais
* **Definição:** Descrevem o comportamento e as funções do sistema.
* **Foco:** O que o sistema deve fazer.
* **Exemplos:** 
  * O sistema deve emitir nota fiscal eletrônica.
  * O usuário deve redefinir a senha via e-mail.

### Requisitos Não Funcionais
* **Definição:** Descrevem os critérios de qualidade, restrições e propriedades do sistema.
* **Foco:** Como o sistema deve funcionar.
* **Exemplos:**
  * O sistema deve processar pagamentos em até 3 segundos.
  * O banco de dados deve ser criptografado com AES-256.

## 2. Técnicas de Elicitação de Requisitos
### 🧠 Brainstorming
* **Objetivo:** Gerar um grande volume de ideias sem julgamento prévio.
* **Dinâmica:** Reunião rápida com a equipe e partes interessadas (*stakeholders*).
* **Vantagem:** Estimula a criatividade e o surgimento de soluções inovadoras.
* **Desvantagem:** Pode perder o foco se não houver um moderador ágil.

### 👥 Entrevistas
* **Objetivo:** Coletar dados detalhados diretamente com usuários e gestores.
* **Tipos:**
  * **Estruturada:** Questionário com perguntas fixas e fechadas.
  * **Não Estruturada:** Conversa livre e aberta sobre o modelo de negócio.
* **Vantagem:** Permite entender profundamente as dores reais do cliente.

## 3. Modelagem e Especificação
### 📊 Diagramas de Requisitos
* **Casos de Uso (UML):** Demonstram as interações entre os atores (usuários/sistemas) e as funcionalidades principais.
* **Diagramas de Atividades:** Mapeiam o fluxo de trabalho passo a passo de um processo de negócio.
* **Diagramas de Sequência:** Mostram a troca de mensagens entre objetos ao longo do tempo.

### 📝 Relatórios Técnicos
* **Documento de Especificação de Requisitos de Software (SRS):** O contrato técnico do projeto.
* **Estrutura Básica:**
  1. Introdução e Escopo.
  2. Descrição Geral do Sistema.
  3. Requisitos Funcionais Detalhados.
  4. Requisitos Não Funcionais e Restrições.

---

## 4. Validação e Feedback
### 📐 Prototipagem
* **Objetivo:** Criar modelos visuais para validar requisitos com o usuário antes do código.
* **Baixa Fidelidade:** Desenhos em papel (*wireframes*) para validar fluxos rapidamente.
* **Alta Fidelidade:** Telas interativas (ex: Figma) idênticas ao produto final.
* **Benefício:** Reduz drasticamente o custo de mudanças tardias no projeto.
